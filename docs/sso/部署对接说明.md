# INOE → Portal 单点登录 部署对接说明

> **B/C P0 更新：**智观仍负责登录。新的 Portal/Console 会取得短期
> QwenPaw 访问凭据；传统智观页面的北向 `X-Inoe-Token` JWT 契约保留。
> AI 管理员必须由部署参数 `QWENPAW_ADMIN_INOE_USER_IDS` 明确指定，
> Docker/Chart 默认名单为 `"1"`；显式空值拒绝管理与高危操作。
> 本版本不新增聊天/记忆用户隔离。
> 以下旧 token 直通描述主要说明初次登录；新的返回凭据与边界见 §4.5。

> 方案:**token 直通**(利用同 host cookie 自动共享)。用户在 INOE 已登录后进入 portal,portal 后端拿 INOE 的登录 token 调 INOE 接口验明身份,建立 portal 登录态。**手机号/密钥全程不经浏览器。**
>
> 适用部署:portal 与 INOE 前端**同 host、不同端口**(k3s NodePort:portal `30083`、INOE 前端 `30081`、INOE 网关 `30080`)。

---

## 1. 原理

INOE 登录后,浏览器在该 host 上有一个登录态 cookie **`Cnos-Inoe-Admin-Token`**(cookie 认 host、不认端口)。因为 portal 与 INOE 同 host,浏览器访问 portal 时会**自动带上**这个 cookie。于是:

```
用户在 INOE 已登录
  → 进入 portal（点 AI 图标 / 直接访问）
  → 浏览器自动带 Cnos-Inoe-Admin-Token cookie 到 portal
  → portal 后端拿 cookie 里的 token 调 INOE /admin/user/getInfo 验证并取用户
  → 建立 portal 登录态（存浏览器 localStorage）→ 进入 portal ✅
```

**关键安全点**:身份(手机号)由后端之间流转,不走浏览器明文;需要密钥的操作只在后端;浏览器只经手用户自己的登录 token。

> 为什么不用文档里的 OAuth2 授权码(`/authorize`→`/token`→`/userinfo`)?那套需要"外部系统凭手机号断言身份",要求 INOE 侧新增"基于当前登录态签 code 并 302"的入口(改造较大)。token 直通利用同 host cookie,**INOE 侧基本零改造**。授权码那套代码仍保留为备用(见 `sso_backend.py` 的 `/exchange`)。

## 3. 组件与代码位置

**Portal 后端**(`src/qwenpaw/extensions/`,挂在 `/api/portal/sso/*`):
- `api/sso_backend.py` — 路由:
  - `POST /token-login` — **主路径**。body `{token}` 或读 cookie `Cnos-Inoe-Admin-Token` → 调 userinfo 接口验证 → 返回 `{access_token, token_type, expires_in_seconds, user}`。
  - `GET /status` — `{configured, authorization_code_ready}`,不含敏感信息。
  - `GET/PUT /sso-settings` + `POST /sso-settings/reset` — 配置读写(密钥脱敏)。
  - `POST /exchange` — 授权码模式(备用,当前不用)。
  - `_extract_user` — 用户字段**白名单**(只放 `userId/username/nickName/phonenumber/deptId/email`),丢弃 `password`/`roles`/`dept` 等,防泄露。
- `api/sso_settings_store.py` — `sso` 命名空间配置(DB>env>默认)。
- `api/portal_backend.py` — 注册 `sso_router`。

**Portal 前端**(`portal/src/`):
- `auth/ssoSession.ts` — 登录态存 localStorage(`qwenpaw.sso.token` / `.user` / `.expireAt`)。
- `auth/ssoConfig.ts` — 开关、登录 URL 派生、兜底守卫 `ensureSsoLogin`、失效重登 `triggerSsoRelogin`、后台校验 `revalidateSession`、带 redirect 的登录 URL `getSsoLoginRedirectUrl`。
- `api/sso.ts` — `tokenLogin` / `exchangeSsoCode` / `getSsoStatus`。
- `pages/SsoCallbackPage.tsx` — 接票页,支持 `?token=` / `?code=` / cookie 三种来源(`/sso/callback` 路由)。
- `main.tsx` — 启动时跑守卫;注册 401 全局 handler。
- 设置页「单点登录」tab(`pages/digital-employee/settingsPanel.tsx` + `api/settings.ts`)。

**INOE 前端**(仓库外 `inoe-ui-monorepo/packages/inoe-ui`):
- `layout/components/Navbar.vue` — 右上角 AI 图标 `toggleAiVisible` → `location.href = this.$store.state.user.systemAI`。`systemAI` 来自后端配置 `sys.systemAI`。

## 4. 配置项清单

### 4.1 前端(portal)

三项都**可选、都有默认**,同 host 标准部署可全不配。构建时 `VITE_*` 与运行时 `window.__PORTAL_RUNTIME_CONFIG__` 两路(运行时优先级见代码,运行时用于免重构镜像调整):

| 运行时 key | 构建时 env | helm 容器 env | 默认 | 作用 |
|---|---|---|---|---|
| `ssoEnabled` | `VITE_SSO_ENABLED` | `PORTAL_SSO_ENABLED` | `false` | SSO 总开关 |
| `ssoInoePort` | `VITE_SSO_INOE_PORT` | `PORTAL_SSO_INOE_PORT` | `30081` | INOE 前端 NodePort(自动拼登录 URL 用) |
| `ssoLoginUrl` | `VITE_SSO_LOGIN_URL` | `PORTAL_SSO_LOGIN_URL` | 自动拼 `http://<当前host>:<端口>/login` | 登录页地址覆盖 |

`ssoLoginUrl` 若要配,**必须是 `http://<ip>:<port>/login` 格式**:指向 `/login`(不是根 `/`,根守卫会丢 `?redirect=`),且**不以 `/` 结尾**。

这三项还共同决定了右上角"切换传统视图"按钮(`navigateToTraditionalView`,直接跳 INOE 前端根路径 `/`,不走登录/SSO 逻辑)跳去哪:`getInoeFrontendOrigin()` 统一解析——配了 `ssoLoginUrl` 就取它的 host+port,没配就用 `当前host:ssoInoePort` 自动拼。两个跳转(SSO 登录 / 切换传统视图)永远指向同一个 INOE 前端地址,不需要分别配置。

### 4.2 后端(portal / qwenpaw)

| 配置 | 位置 | 默认 | 作用 |
|---|---|---|---|
| INOE 网关地址 | 设置页「平台」tab / env `INOE_API_BASE_URL` | 集群内 `http://gateway:8080` | token 直通调 userinfo 的基址(网关根) |
| `sso_userinfo_path` | 设置页「单点登录」tab | `/admin/user/getInfo` | 取用户信息的路径(相对网关根);绝对 URL 也可 |
| `sso_client_id/secret/redirect_uri`、`sso_gateway_base_url` | 设置页「单点登录」tab | 空 | **仅授权码模式**,token 直通用不上,留空 |

> token 直通最终请求 = INOE 网关地址 + `sso_userinfo_path`。集群内默认即 `http://gateway:8080/admin/user/getInfo`。

### 4.3 业务接口真实校验与短时缓存

后端 `QWENPAW_SSO_TOKEN_REQUIRED` 默认开启（兼容
`COPAW_SSO_TOKEN_REQUIRED`）。受保护的 HTTP API 不再仅检查 token 非空，
而是调用上述用户信息接口确认登录态。客户端通过 `X-Inoe-Token`
传递令牌；浏览器导航和下载也可使用 `qwenpaw_sso_token` Cookie。
显式携带 header 时优先使用 header，空值或无效值不会回退 Cookie。

每个后端进程使用独立的内存缓存，无需 Redis 或其他 PaaS：

- 成功结果缓存 15 秒，上限 1024 条，按认证地址及 token 的 SHA-256
  摘要区分；只保留公开身份字段，不缓存明文 token。
- GET/HEAD 及 `POST /api/console/chat`、`POST /api/console/chat/task`
  （含 Agent-scoped 路径）可复用缓存。其他受保护写请求，包括批准审批、
  POST 批量删除和设置保存，进入接口前重新在线校验。
- 同一 token 的并发在线校验合并；连接池复用；在线校验超时为 5 秒。
  缓存命中不延长有效期，JWT 中可解析的 `exp` 只用于缩短缓存期限，
  不作为身份验证依据。
  在线校验耗时计入 15 秒窗口；连接池不复用认证服务返回的 Cookie，
  每次仅用当前请求 token 验证，避免不同用户的认证 Cookie 混入。
- 缺少 token 返回 `401 SSO_TOKEN_REQUIRED`；无效 token 返回
  `401 SSO_TOKEN_INVALID`；认证服务异常返回 502/503/504 和
  `SSO_VALIDATION_UNAVAILABLE`，不放行、不复用过期缓存。
- 校验后的身份写入 `request.state.sso_user`，令牌写入
  `request.state.inoe_token` 和请求上下文，Cookie 与 header 的下游
  INOE 调用使用同一已验证凭据。SSE 在入口校验一次，不逐事件校验。

注销/撤销后的已有成功缓存最多可能继续放行约 15 秒，前提是智观
用户信息接口本身能识别注销及撤销。进程重启会清空缓存。
这不是多租户授权或会话/记忆隔离方案，也不代表长聊天中的工具写操作
已在执行前重新校验；这些仍需业务授权和工具治理单独约束。
现有精确公开接口白名单保持不变；它们不走上述门禁。

### 4.4 无 MCP 部署的协同调用与人工指南

`list_agents`、`chat_with_agent` 及后台协同任务通过共享 HTTP 客户端，
携带当前请求的 `X-Inoe-Token`，仍由业务 API 的真实校验门禁验证。
请求凭据只允许转发到配置中的 Agent API 地址（同协议、端口及主机，
允许等价 loopback 地址），不会转发给工具指定的其他服务。

技能脚本使用子进程独立环境中的 `INOE_API_TOKEN`；
`qwenpaw agents/chat` 等 CLI 使用 `QWENPAW_REQUEST_INOE_TOKEN`
（兼容 `COPAW_REQUEST_INOE_TOKEN`）转发同一用户凭据。
这些变量只由当前请求传入子进程，不写入全局环境、不出现在命令行参数中，
也不回退共享管理员凭据。沙箱明确屏蔽凭据或采用环境白名单时保持原限制；
受治理禁止的 CLI/shell 仍不得执行。真正失效的 token 仍返回 401，
不会通过放宽本机地址鉴权来绕过。

Portal 原始 user 文本不再追加 `[CMDB 人工处置指南约束]`：
前端只发送 `request_context.portal_manual_fault_guidance=true`，
服务端 Hook 注入固定的系统上下文。历史显示忽略 system 消息，并兼容
旧版本追加的完整约束后缀；不改写已存会话文件。
指南通过 AgentScope 的 `on_system_prompt` middleware 加入模型系统提示词，
不把 system 消息插入 `reply_stream` 的用户输入列表，也不保存到用户消息。
PRE_EXECUTE 的注册接线依赖锁定的 AgentScope 2.0.2
`_system_prompt_middlewares` 列表；SDK API 不兼容时明确失败，
不能静默丢失约束，升级 SDK 时必须回归实际模型输入准备路径。

本修复必须同时更新 Portal 与后端。涉及核心的最小接线为
`agents/tools/agent_management.py`（共享客户端请求头）、
`agents/tools/shell.py`（子进程凭据环境）及 `app/_app.py`
（注册扩展 Hook）。逻辑保留在 `extensions/`，因为只改 Portal
不能覆盖工具/CLI 的内部 HTTP 请求，且 Hook 需进入启动时的固定注册列表。
风险主要是子进程环境与 Agent API 地址兼容性，必须回归多 Agent、
前台/后台协同和沙箱屏蔽策略。回滚应将本补丁的前后端一起回退，
保留真实 token 校验，不通过关闭门禁处理兼容问题。

### 4.5 本地访问凭据、管理员与生产执行边界

智观 token 验证成功后，服务端用 QwenPaw 原生签名/校验机制换发带
`qp1.` 类型标识的访问凭据，最长 600 秒，不超过可解析的上游 JWT 到期时间。
它不是标准三段 JWT，也不是共享管理员身份。无需注册本地密码账号，
不依赖 `QWENPAW_AUTH_ENABLED` 或「尚未注册用户则放行」的旧分支。

| 调用方 | 凭据 |
| --- | --- |
| 传统智观北向 | `X-Inoe-Token: <有效智观 JWT>`，真实在线校验及 15 秒缓存 |
| 新 Portal/Console、CLI/协同 | `X-QwenPaw-Access-Token` 或 `Authorization: Bearer qp1.…` |
| 旧 Portal 缓存页面 | 兼容 `X-Inoe-Token` 中的 `qp1.`，按本地凭据验证，不转发给智观 |
| 导航/下载 | 服务端 `qwenpaw_access_token` HttpOnly、SameSite=Strict Cookie |
| 智观业务接口 | 对应会话中的原始智观 token，不使用本地 token |
| 本机模型 Adapter | 独立、仅限模型路径的能力密钥；不用于普通 AI API |

本地会话映射及业务 token 密文保存在秘密目录的 `sso_access_sessions.db`。
缓存/映射键不保存明文访问 token，签名密钥沿用秘密存储。
本地会话同时绑定当前认证接口；认证来源配置改变后旧会话立即失效。
本地凭据普通查询先本地验签及校验会话；管理写请求在线复验智观登录态。
显式无效/空凭据、不同身份的混合凭据不能通过 Cookie 或其他身份兜底。

Portal 的可见页及 Console 每约 60 秒续验关联智观会话；
认证服务故障不触发密码登录，确切失效才走智观重登录。
Console 遇到本地 token 的 401 会重载当前地址重新进行 SSO 引导，
不落入 QwenPaw 原生密码页。环境特殊时同时配置
`QWENPAW_INOE_LOGIN_URL` 与 Portal 的登录地址，默认同 host 的 30081。
同一浏览器会话的续期 token 属于同一家族，本地注销撤销该家族的旧、新 token；
在途续期不能重新激活已注销家族。其他浏览器会话不因此被注销。
Portal 换发请求有 10 秒客户端截止时间，Cookie 注销清理最多等 2 秒；
401 检查等待重登录跳转完成，清理失败明确记录后继续本地退出，不无限卡住。
认证来源暂不可用时保留原会话的剩余有效期，不伪造续期；服务端注销接口
不可达时不能保证已经撤销会话家族，不能把本地状态清空当作服务端撤销成功。
Console 在插件及业务组件挂载前完成认证，避免插件首次 401 先跳密码页。
受控 Portal 入口提供 `/console/`、`/console/assets/` 及 `/api/` 反代，
不需要把后端 NodePort 重新开放。新 Console 必须使用配套的后端和 Portal nginx。
**没有智观服务端撤销通知时，外部客户端的本地只读凭据仍可能存活至其
600 秒有效期；这不是即时全平台注销。**长任务的高危执行会再次验证凭据，
不因前端已续期而自动延长旧任务的执行授权。

管理员 ID 白名单用逗号分隔，仅信任智观返回的稳定 `userId`：
`QWENPAW_ADMIN_INOE_USER_IDS`（兼容 COPAW 前缀）。
Docker/Chart 默认 `"1"`，可用部署环境覆盖为其他逗号分隔列表；
设置为 `""` 拒绝全部管理/高危操作。直接从源码启动且未设置此参数时，
策略仍按空名单拒绝，不从用户名或 INOE 返回的角色字段猜测管理员。
未配置的普通登录用户不能访问 envs、模型/MCP/技能管理、系统设置、审批等入口。
审批仅允许白名单管理员处理其可信身份绑定的请求，且保留 root session 检查。
HTTP POST 的 batch-delete/delete/remove 与 DELETE 一样受删除禁用策略约束。

`QWENPAW_PRODUCTION_GUARDS` 默认开启：

- 任意 shell、管道、展开、`python -c`、凭据命令行参数默认拒绝；
  仅允许固定协同 CLI、受管种子内明确列入的只读脚本。
  受管脚本及依赖树须匹配种子哈希，新增未声明 Python/本机扩展也会被拒绝。
  自定义脚本只能由部署的 `QWENPAW_ALLOWED_SCRIPT_HASHES` JSON 哈希白名单批准。
- 文件工具即使关闭普通 approval_level，也不能读取/改写秘密、备份、
  审计、进程环境或系统凭据文件；路径解码、Unicode 规范化和解析后复查。
  附件的 file:// URL 在媒体处理之前执行相同检查；远程附件必须在
  `QWENPAW_ALLOWED_MEDIA_HOSTS` 声明，不能通过附件让模型读取私密存储。
  Skill 环境配置不能覆盖安全启动参数或认证路由；不能以 Skill 环境
  临时注入管理员 ID、关闭守护或改变认证来源。
- 高危及未分类工具要求可信管理员、执行前在线验证和人工审批；
  审批参数不能变更、重放，沙箱拒绝不能通过审批切换成无沙箱执行。
- MCP 连接在读取凭据前校验端点，默认只允许 loopback/集群服务 FQDN。
  其他批准主机用 `QWENPAW_MCP_ALLOWED_HOSTS` 声明；stdio 必须在
  `QWENPAW_MCP_ALLOWED_COMMANDS` 中声明精确命令。
  空/未知 transport 不得绕过检查，传输不能跨来源转发凭据。
  未分类/写 MCP 工具在未接入强制审批业务连接器前禁用；
  只读工具须在 `QWENPAW_READONLY_TOOL_NAMES` 明确声明，不能凭名称猜权限。
- 模型 Adapter 不向上游转发 `qp1.` Authorization；模型能力密钥也不能
  访问 envs/审批等其他 API。本地 API 目标仅限 loopback 或明确的
  `QWENPAW_INTERNAL_API_ORIGINS`；本地模型客户端不跟随重定向转发密钥。

身份、生产策略、代理信任、内部来源等安全参数只能从受控部署配置设置，
不能由环境变量页面/PUT envs 修改。旧 envs.json 中的这些值不再注入进程。
仅独立本地开发可显式设置 `QWENPAW_PRODUCTION_GUARDS=false` 保留原生
单用户管理/审批流程；此时 SSO 开关仍独立生效。生产镜像/Chart 默认开启
守护，不得用开发配置上线。
包括旧的培训 `SSO_TOKEN_REQUIRED=false`：若确需受控维护，必须在部署层显式设置；
生产守护开启时，即使关闭普通 SSO 门禁，也不会匿名放行管理/高危操作。
代理头默认不用于免认证 IP 判断；仅在
`QWENPAW_TRUSTED_PROXY_CIDRS` 明确配置时从右向左解析可信链。
Cookie 方式的受保护写请求必须有匹配来源；TLS 在外层终止或跨域部署时，
用 `QWENPAW_BROWSER_ORIGINS` 明确批准浏览器 Origin。Bearer/显式请求头
北向调用不需要伪造 Origin。生产不接受带凭据的 `CORS_ORIGINS=*`；
跨域传统页面要声明真实 Origin。生产发布需配套 TLS，不能把内网临时 HTTP
测试结果当作公网凭据传输安全验收。

交付已移除秘密配置及其主密钥的镜像备份、真实默认 INOE token，
主进程非 root、禁止提权、丢弃 capabilities；后台 Service 默认 ClusterIP，
NetworkPolicy 限制入站与出站。升级前必须准备 PVC 所有权、模型/业务 Secret、
管理员 ID 和必要模型/MCP网络对端，不能为了恢复可用性临时放开全部网络。
NetworkPolicy 依赖现场 CNI enforcement；外部 web-check/MCP 服务自身的
公网入口不由 QwenPaw 的策略自动保护，需由其维护者单独收口/鉴权。
日志新增可信操作人，但本地 SQLite 审计不等于独立不可篡改归档。

核心接线包括 auth 的统一认证标记、工具/文件执行检查、审批归属及
MCP handler/transport 安全边界。签名与业务凭据逻辑仍在扩展层。
这些调用入口由核心直接执行，仅增加扩展路由不能拦截绕过审批的调用。
风险范围涉及所有 Agent 的工具执行、附件处理、模型调用与 Console 加载，
不是仅影响 Portal；生产默认拒绝未声明工具/网络，旧部署需先补齐声明。
发布前后端、技能种子与 Chart 必须配套；回滚先限制入口、恢复同版制品，
不得退回公网免认证、root 或镜像内共享密钥。用户模型、会话和历史不自动迁移归属。
现有助手、历史及业务看板缓存仍是共享域，不构成用户/租户数据隔离。
仅适合获准共享同一业务域的使用者；不同授权业务域不能靠管理员名单
划分数据访问，应另行隔离实例或实施后续数据域改造。

## 5. 部署(helm)

### A 阶段可靠性修复

- 告警 `execute()` 的显式 token 参数优先；未传时读取当前请求上下文，
  再读取授权执行环境。显式空值/失效值不回退其他身份。
  `diagnostic.stage`、HTTP 状态和业务 code 用于区分入口、脚本及网关错误；
  查询失败不能作为零告警。三份维护源保持一致，order/resource 由
  `universal-seed.json` 的 query 共享源生成，并纳入哈希同步清单。
- knowledge 模型遵循「独立配置 → 现有全局默认 → 增强不可用」；
  不修改用户模型配置、不借用 gateway。显式模型选择必须传到模型工厂，
  模型创建/调用/流读取错误均转换成知识库 LLMError。

- 健康接口和知识库页面显示实际模型来源及配置就绪状态，
  不等同实际模型连通性。检索返回 `flags.degraded` 及阶段原因；
  总结失败返回 `skipped`，与无匹配资料分开。
- 通用 CLI 与协同工具共享请求凭据传递规则；Docker 启动也运行
  `sync_managed_seed.py`，与 Helm 同步机制一致，保留运行数据及模型选择，
  受管文件变更有备份。不能只换镜像而继续使用旧的持久卷技能。

核心新增接线还包括 `cli/http.py`（通用 CLI 请求头）和
`agents/model_factory.py`（修正显式 model_slot 被清空）。
后者直接影响知识库选择与模型实际调用一致性，其他调用者的 Agent/全局
默认顺序保持不变。发布应同时升级后端、Portal、技能种子，

现有公开白名单不调整。

### C5 告警统计口径

上游 `hisAlarmList` 必须传时间窗口，没有可核实的全量活动告警统计接口。
API/页面展示真实起止时间、时区和 `complete=false`，不能称为全量活动数。
`total` 保留上游窗口总数；`visibleTotal` 是当前可见集合数，
`pageTotal` 是返回页数，截断/过滤不能把后两者当作上游总数。
统计失败或总数不可验证时返回 `null` 和来源状态，不用零值兜底。
缓存回退明确标为 stale；空窗口结果不能证明系统健康。
告警线程池显式复制当前请求上下文，使用该请求经验证的 INOE 业务凭据；
没有请求主体的后台任务才使用部署配置的业务凭据。

**运行时注入机制**:portal 镜像启动脚本 `deploy-all/portal/docker-entrypoint.d/40-runtime-config.sh` 在 pod 启动时,从**容器环境变量**生成 `/usr/share/nginx/html/runtime-config.js`(nginx 对该文件 `no-cache`)。`index.html` 先于 app 加载它,设置 `window.__PORTAL_RUNTIME_CONFIG__`。

**结论:改 SSO 配置 = 改 helm values 的 `PORTAL_SSO_*` → `helm upgrade`(pod 重启)→ 生效,不用重构 portal 镜像。**

helm values 位置:`deploy-all/helm/cnos-inoe-agent/values.yaml` → `digital-workforce-portal.env`:

```yaml
digital-workforce-portal:
  env:
    # ...
    PORTAL_SSO_ENABLED: "true"         # 生产配合后端认证一起启用
    # PORTAL_SSO_INOE_PORT: "30081"    # 仅 NodePort 改了才设
    # PORTAL_SSO_LOGIN_URL: ""         # 仅不同 host / 特殊登录路径才设
```

1. **重构并推送前后端镜像**(带上本轮改动):
   - portal 镜像:本轮前端新增了"读运行时 SSO 配置"的代码,旧 bundle 不认这些 key,**必须重构一次**;之后 SSO 前端项都可运行时调,不用再重构。
   - qwenpaw 镜像:本轮后端新增 token-login 等,也需重构。
2. 先在验证环境配置管理员 ID、运行时 Secret、TLS/Origin、网络对端和

3. 验证登录、本地续期/注销、传统 JWT 北向接口和角色边界；确认聊天、

## 6. INOE 侧需要的改动

### 入口1(点 AI 图标进 portal)—— 不用改

同 host cookie 自动带,`toggleAiVisible` 的裸跳转即可。只需确认 **`sys.systemAI` 配置指向 portal 地址**(同 host 的 `:30083`)。

### 兜底"登录后自动回 portal" —— 需改 1 处(可选)

portal 兜底跳转已带上 `?redirect=<portal完整URL>`。但 INOE 登录成功默认是**站内跳转**,不会跳外部 portal。要自动回,请在 INOE 登录成功回调加判断:

```js
// 登录成功后
if (/^https?:\/\//.test(this.redirect) && isAllowed(this.redirect)) {
  window.location.href = this.redirect          // 外部 URL → 回 portal
} else {
  this.$router.push({ path: this.redirect || '/' })  // 站内保持原样
}
```

⚠️ **`isAllowed` 白名单必须有**——只允许回 portal 的 host,否则是**开放重定向漏洞**。`redirect` 是完整 URL,校验其 host 即可。

**不改也能用**:登录后停在 INOE 首页,用户点 AI 图标回 portal(此时 cookie 已种,直通登录),只是多一步。

## 7. 测试方法

### 后端(不依赖浏览器)

```bash
# 用一个有效 INOE 登录 token（从浏览器 cookie Cnos-Inoe-Admin-Token 取）
curl -X POST http://<qwenpaw>/api/portal/sso/token-login \
  -H "Content-Type: application/json" -d '{"token":"<token>"}'
# 期望：200，返回 {access_token, user:{userId,username,...}}
```

### 前端(浏览器)

- **直通**:控制台 `document.cookie="Cnos-Inoe-Admin-Token=<有效token>; path=/"` → 打开 portal 首页 → 应自动登录。
- **接票**:访问 `http://<portal>/sso/callback?token=<有效token>` → 建立会话 → 跳首页。
- **失效重登**:cookie/会话里放无效 token → 刷新 → localStorage `qwenpaw.sso.*` 被清 + 跳 INOE 登录页。

### 本地开发注意

本地 portal 是 `localhost`、INOE 是远程 IP = **不同 host,cookie 到不了本地**,SSO 开着直接访问会**一直循环跳 INOE**(拿不到有效登录态)。本地:
- 日常开发用 `VITE_SSO_ENABLED=false`;
- 要测 SSO:`VITE_SSO_LOGIN_URL` 指向公网 INOE 登录页,再用 `?token=<新鲜token>` 或 devtools 种有效 cookie 手动建会话(token 有时效,会过期)。

## 8. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 访问 portal 一直循环跳 INOE | SSO 开着但拿不到有效登录态。生产:确认同 host、cookie 带过来了、token 未过期。本地:跨 host 必然如此,用 `VITE_SSO_ENABLED=false` 或手动喂 token。 |
| 有效会话刷新后被踢 | token 过期(后端返回"登录状态已过期");或 cookie 是旧值——已修复为**校验会话自己存的 token**,非 cookie。 |
| `/userinfo` 404 | 文档路径 `/auth/oauth2/userinfo` 在环境里未部署(网关 strip `/auth`)。改用 `sso_userinfo_path=/admin/user/getInfo`(实测通)。 |
| 后端 401「缺少 INOE 登录凭证」 | 请求没带 token 也没 cookie。检查同 host、cookie 的 SameSite/domain 是否让浏览器带到 portal。 |
| 登录后没回 portal | INOE 登录回调未支持外部 redirect(见 §6),或走"点图标回来"的退路。 |
| redirect 参数丢失 | `ssoLoginUrl` 配成了根 `/`。改成 `/login`。 |

## 9. 安全说明

1. **手机号不走浏览器明文**;需要密钥的加密/加签只在后端(前端做会泄露密钥)。
2. token 直通传的是**用户自己的 INOE 登录 token**(会过期、登出即失效),浏览器只经手它;不传手机号、不传密钥。
3. 后端 `_extract_user` **白名单**只放 6 个字段,`getInfo` 返回的 `password`(bcrypt 哈希)、`roles`、`dept` 等**不会流到浏览器**。
4. 登录态存 localStorage,存在 **XSS 被盗风险**(这是 INOE 完整登录态)。**生产可评估**改为后端 httpOnly Cookie 会话。
5. 兜底自动回 portal 的 INOE 登录 redirect,**必须做 host 白名单**,防开放重定向。
