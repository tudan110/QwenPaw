# 鉴权整体方案与旧版本临时处理方案

> 本文整理已入库实现、历史临时措施和建议预案；

## 1. 方案目标与边界

在保留智观 SSO、现有 JWT 接口兼容的同时，让正常聊天、内置技能、脚本和智能体协同使用正确身份执行；管理及高风险操作必须受限，不能靠共享管理员 token 恢复功能。

鉴权分为三层，排障时分别核对：

| 层级 | 负责内容 | 不能替代的能力 |
| --- | --- | --- |
| 登录身份 | 验证 INOE 用户、换发本地会话、判定管理员 | 登录成功不代表所有工具可执行 |
| 执行权限 | 工具注册、脚本完整性、参数和文件范围、MCP、人工审批 | 放行脚本不代表获得上游数据权限 |
| 业务权限 | INOE、CMDB 等接口使用的真实业务凭据及其权限 | 本地管理员、后台协同凭据不自动获得 INOE 权限 |

当前方案不等于完整的用户/租户数据隔离：会话、历史、记忆和部分业务缓存仍需单独评估。不能据此承诺全平台即时注销或所有扩展工具均已可用。

## 2. 登录、访问与注销

### 2.1 登录及凭据换发

1. 用户先登录智观。当前同主机、不同端口的部署可通过浏览器携带 `Cnos-Inoe-Admin-Token` Cookie 接入。
2. Portal 调用 `POST /api/portal/sso/token-login`，后端向 INOE userinfo 接口验证真实身份，默认路径为 `/admin/user/getInfo`。
3. 校验成功后签发 `qp1.` 本地访问凭据，最长 **600 秒**；若上游 JWT 到期时间可解析，不能超过该时间。`qp1.` 是带类型前缀的本地签名凭据，不是标准三段 JWT。
4. 普通 API 使用 `X-QwenPaw-Access-Token` 或 `Authorization: Bearer qp1.…`。下载、浏览器导航通过 `qwenpaw_access_token` Cookie 携带身份。
5. 会话保存在 `SECRET_DIR/sso_access_sessions.db`：本地 token 存哈希，上游 INOE token 加密保存，并绑定认证端点摘要；认证来源变化后旧会话失效。

下载 Cookie 为 HttpOnly、SameSite=Strict；Secure 取决于后端识别的请求协议。HTTP 部署不具备 TLS 传输保护，HTTPS 代理须验证协议识别和 Cookie 实际属性。

### 2.2 兼容和校验频率

- 保留 `X-Inoe-Token: <有效 INOE JWT>` 的真实校验方式；兼容旧 Portal 将 `qp1.` 放入该头，后端将其识别为本地凭据，不转发给 INOE。
- 本地普通读取走本地验签及会话查询；管理和大多数写请求在线复验 INOE。userinfo 缓存默认 **15 秒、每进程最多 1024 条**，按认证地址和 token 摘要区分，并合并同 token 并发校验。
- GET/HEAD、聊天提交及注销等指定请求可使用该短缓存；缓存命中不延长有效期。JWT 解析仅用于缩短期限，不能替代真实验证。
- Portal/Console 约每 60 秒续验。续期沿用同一会话家族，注销撤销该家族的新旧凭据，并处理异步响应覆盖注销状态的竞态。
- 本地注销不代表注销其他浏览器或 INOE 全平台会话。上游撤销没有通知时，本地只读凭据可能继续有效至其期限，最长 600 秒；高风险执行还需复验。

原生 `QWENPAW_AUTH_ENABLED` 是独立本地密码认证开关，不代替 SSO；已建立可信联邦身份时跳过重复原生认证。

### 2.3 公开接口、来源与错误

公开入口仅限对应方法：GET `/api/portal/health`、GET `/api/portal/sso/status`、POST `/api/portal/sso/token-login`、POST `/api/portal/sso/clear-login-cookie`。`/sso/session`、员工状态及知识检索等接口仍受保护。

`POST /api/portal/sso/exchange` 虽在门禁白名单内，但处理器固定返回 404，状态字段 `authorization_code_ready=false`；填写 client 配置不能启用授权码登录。OPTIONS 和非 API 静态资源不由该 SSO 中间件拦截。

- `/portal-api/...` 归一化为 `/api/portal/...`，`/copaw-api/...` 归一化后同样鉴权，不能通过代理别名绕过。
- token-login、清除登录 Cookie，以及携带 Cookie 的写请求受同源检查；额外来源通过 `QWENPAW_BROWSER_ORIGINS` 精确配置。显式 token 的 CLI 可在符合条件时不带 Origin，仍须提供有效身份。
- URL query token、请求体 `user_id`/`source`、伪造代理头不构成可信身份。普通受保护 API 的显式无效凭据不借 Cookie 回退；token-login 自身存在独立的已有 Cookie 兼容分支。
- 缺少、过期、伪造或上游明确拒绝的凭据返回 401；权限不足返回 403。上游通用 500、非 JSON、超时等保留为 502/503/504 并拒绝访问，不能统一改成“登录过期”。

## 3. 管理员与高风险操作

管理员仅依据**已验证的稳定 INOE userId**及 `QWENPAW_ADMIN_INOE_USER_IDS` 判定，不信任昵称、客户端 user_id 或上游 roles 字段。源码未配置时为空名单；当前交付 Chart/Docker 示例为 `"1"`，部署必须换成现场确认的 ID，不能沿用示例假定角色正确。

生产守护开启时，供应商、环境变量、MCP、技能、安全、备份、工作区、审批等管理接口要求管理员；明确允许的聊天、上传、知识检索仍向已登录普通用户开放。

高风险工具还需在线复验和人工审批。审批绑定命令、参数及相关输入内容摘要，变更输入、重放或身份过期不能复用。沙箱拒绝不能通过审批变为无沙箱执行。

## 4. 协同、后台任务与脚本凭据

### 4.1 在线与手动协同

在线协同优先传递当前本地访问凭据，其次传递当前 INOE token；身份上下文覆盖完整 SSE 生命周期，不把个人凭据写入全局进程环境。登录用户手动触发任务保留用户身份。

子进程按实际需要注入以下变量，先清理继承的旧请求凭据；显式空值屏蔽及沙箱环境白名单继续有效：

- `QWENPAW_REQUEST_ACCESS_TOKEN`：当前本地访问凭据。
- `QWENPAW_REQUEST_INOE_TOKEN`：当前 INOE 用户凭据；业务脚本按需使用 `INOE_API_TOKEN`。
- `QWENPAW_REQUEST_COLLABORATION_TOKEN`：受限后台协同凭据。

凭据只转发到可信 API origin 及允许的 API 根路径，校验协议、主机和端口；额外地址由 `QWENPAW_INTERNAL_API_ORIGINS` 明确声明，不向任意工具 URL 或重定向目标转发。

### 4.2 自动 cron 协同

自动调度通过 `scheduled=True` 明确进入服务模式，不继承调度线程残留的个人身份。任务执行期间签发随机 `qc1.` 租约，以 `X-QwenPaw-Collaboration-Token` 传递，SQLite 只存哈希、任务标识和期限。

| 项目 | 当前约束 |
| --- | --- |
| 生命周期 | 默认按任务超时加 30 秒计算，最少 30 秒、最多 86400 秒；任务退出或异常后撤销 |
| 允许能力 | 智能体发现、聊天、异步协同提交及限定格式的结果查询路径 |
| 禁止能力 | 管理设置、上传、fork、通用管理；不能与用户 token、Cookie 等混用 |
| 业务权限 | 租约不提供 INOE userId 或业务权限；业务查询仍依赖合法业务凭据 |

调用方应等待子协同完成后再结束 cron。租约不是永久后台账号，其他后台入口也不会自动获得它；记录 job_id 不等于已实现所有任务资源的归属隔离。

### 4.3 CMDB 等业务脚本

委派子进程缺失、空白或无效的请求身份不能静默回退共享 CMDB 账号。元数据缓存按连接和身份摘要隔离，不保存原始 token，并清理旧格式缓存；该改造不等于全系统数据隔离。

## 5. 内置技能、Office 与 MCP 的执行边界

生产守护 `QWENPAW_PRODUCTION_GUARDS` 默认开启。工具在运行时可发现，仍须在治理注册表中正确注册；unknown 工具在用户白名单之前直接拒绝。

- 内置脚本使用固定入口、参数契约及技能/依赖树完整性校验。通用 shell、拼接命令、任意 Python、秘密路径及文件越界不因“系统技能”而自动开放。
- `QWENPAW_ALLOWED_SCRIPT_HASHES` 为已有自定义 Python 脚本提供部署批准入口，不授予全部参数、文件、网络或业务权限；不要把模型临时生成的脚本自动加入。
- 后端、技能文档和 seed/manifest 必须配套发布；已有 PVC 的受管文件也要同步。默认 seed 路径 `/app/share/qwenpaw-seed`，污染文件走维护预览、审核隔离与备份恢复流程。
- 报告使用受控 `export_report`，默认 PDF，也支持 Word、Markdown。Office 结构化入口保留原文件；其 PDF 转换属于文本重排，不承诺原始版式还原。
- 已审核只读操作通常不增加管理员审批，但仍遵守工作区治理和沙箱；正式 CMDB 导入及其他高风险写入需管理员审批。不能概括成“所有脚本都要确认”或“内置脚本全部免确认”。

MCP 在 Portal「配置中心 → MCP 管理」配置；当前页面管理 gateway，内部智能体按自身工作区配置。保存后面向新请求生效，并需连接就绪；已发出的远程调用不会被撤回。

启用且 ready 时优先 MCP；停用/未配置时，已有适配的内置技能可走受管脚本。认证失败、权限拒绝、空结果或白名单排除不能触发绕过；仅明确传输失败的只读请求允许一次已有脚本回退，写结果不明时不自动重放。自定义 MCP 没有通用脚本替代。

MCP 目标受 `QWENPAW_MCP_ALLOWED_HOSTS` 约束，stdio 按 `QWENPAW_MCP_ALLOWED_COMMANDS` 精确批准命令及参数；只读工具名单也不绕过其他安全层。模型 Adapter 的 `X-QwenPaw-Model-Key` 仅适用于模型接口，不能把 `qp1.` 当作上游模型密钥。

### 当前明确未解决的阻塞

截至代码基线，`ProcessOfficeDocument`、`WriteSkillContext` 已有工具实现，但遗漏治理注册及函数名映射。11 月 19 日现场均返回 `governance: '…' is denied by policy`。

影响 Office 结构化读取/生成/修改，以及依赖 JSON 上下文准备的 CMDB/FDE 对话引导；**独立 CMDB 页面文件解析未完成验证，不能直接认定失败**。独立报告导出不依赖这两个入口。

这不是待人工审批，也不能靠 policy.yaml 白名单、关闭 SSO 或 MCP 开关解决。后续应补齐治理注册和映射，明确分类语义，并增加真实 `PolicyGuardedTool + ResourceGovernor` 调用链测试；若采用 internal 分类，必须评估绕过普通用户规则/严格模式的含义，保留生产边界和工具自身输入约束。本文仅记录待修复项。

## 6. 部署配置基线

以下为配置示意，地址和管理员 ID 须使用现场值，凭据通过 Secret 注入：

```yaml
# 后端部署环境
QWENPAW_SSO_TOKEN_REQUIRED: "true"
QWENPAW_PRODUCTION_GUARDS: "true"
QWENPAW_ADMIN_INOE_USER_IDS: "<已确认的稳定 INOE userId>"
QWENPAW_INTERNAL_API_ORIGINS: "http://qwenpaw:8088"
INOE_API_BASE_URL: "http://gateway:8080"
QWENPAW_SSO_USERINFO_PATH: "/admin/user/getInfo"

# Portal 独立容器环境
PORTAL_SSO_ENABLED: "true"
```

- `QWENPAW_*` 存在时优先于兼容的 `COPAW_*`，即使主键为空也不回退；建议仅保留一套前缀。
- SSO、生产守护、管理员、内部可信地址和请求凭据等安全项只能在部署层维护，不能通过环境变量页面或 Skill 覆盖；修改后按既定部署策略重启相关实例。
- INOE 地址、userinfo 等设置可能被设置库中的覆盖值优先采用，排障须核对有效来源。userinfo 允许绝对 URL；默认相对路径按 `INOE_API_BASE_URL` 拼接。`SSO_GATEWAY_BASE_URL` 不替代该默认拼接规则。
- Portal 启动脚本生成 `runtime-config.js`；支持该机制的 bundle 可通过重启应用运行时配置，更早前端仍需配套构建。前端开关不构成后端安全门禁。
- 当前 Chart 使用单 worker、RWO PVC 和 Recreate 策略，按交付配置升级，不能擅自照搬多副本滚动方案。保留 secret 目录及加密主密钥，不通过删除数据库“修复”解密问题。

## 8. 旧版本临时恢复预案

本节是建议操作，尚未在目标环境实施。优先补齐地址、来源和身份传递，再选择配套兼容补丁；不要先关闭生产守护。

### 8.1 按故障选择最小处理

| 场景 | 临时处理 | 恢复条件 |
| --- | --- | --- |
| 旧客户端未传身份 | 保持门禁，补传调用者有效 `X-Inoe-Token`；支持统一 CLI 的版本由受控父进程注入当前请求环境 | 发布正式身份传递接线；不把个人 token 固化到全局环境、命令行或共享配置 |
| 新前端与老后端凭据不兼容 | 核对后端是否支持 `qp1.`；采用同版前后端，或提供经过审核的 JWT 兼容接线 | 配套发布；不能伪造 qp1 或只改前端登录按钮 |
| 自动后台协同缺少身份 | 暂停受影响自动任务防重复，临时用已登录用户前台/手动协同；验证该版本确实传递用户身份 | 升级含受限租约的后端和种子，验收自动任务；不配置共享管理员 token |
| 子脚本有登录但没有业务权限 | 补传当前业务身份，核对可信 API 地址及上游授权 | 当前用户业务查询成功；缺失身份不能回退共享账号 |
| seed 不一致或受管目录污染 | 发布同版 seed；先预览差异、备份并审核隔离污染文件 | 完整性就绪；不以 chmod、关闭校验或随意替换哈希处理 |
| Office/JSON 工具 unknown | 采用最小治理注册补丁并测真实调用链；报告先走已有 export_report | 补丁验收；人工审批及线上策略白名单不能修复注册遗漏 |
| 旧版没有受控报告导出 | 使用人工转换，或交付配套受控导出兼容包 | 验证生成、下载、中文内容及身份保护；不开放任意 Office Python |
| 上游校验返回通用 500/超时 | 保持拒绝访问，修复地址、网络或上游协议，展示真实故障 | userinfo 正常；不把所有 500 猜成 token 过期或切换匿名模式 |

### 8.2 最后手段：隔离实例的培训/维护兼容

仅在无法及时补丁、确需运行无凭据旧客户端时考虑；先封闭原有业务入口，使用独立隔离实例或额外外部认证，限定操作者、数据、时间窗口及恢复负责人。普通业务数据可能因此匿名可读，不能作为对公网或办公网常态开放方案。

1. 记录当前镜像/提交、配置及持久化兼容性；备份设置和密钥，确认实际版本的开关分支。
2. 在部署层修改以下项目，按既定策略重启后端及涉及的 Portal。示例仅用于**已支持生产守护的版本**：

   ```yaml
   # 仅隔离维护实例；不是生产基线
   QWENPAW_SSO_TOKEN_REQUIRED: "false"
   QWENPAW_PRODUCTION_GUARDS: "true"
   # 仅当需要兼容前端流程，且 bundle 支持此配置时
   PORTAL_SSO_ENABLED: "false"
   ```

3. 当前基线中，该设置仅放过没有用户/协同凭据的普通请求；管理接口仍需可信身份，模型 Adapter 仍需认证，已有无效凭据仍可能被拒绝。原生密码认证独立，不应为便利连带关闭。
4. **11 月 4 日/10 日版本不具备上述管理保护承诺**，`PRODUCTION_GUARDS` 在引入前设置无效；无法证明隔离有效时不采用此预案。
5. 此模式不为 INOE 查询、CMDB 写入或高风险工具生成身份，也不能恢复治理 unknown 的工具。`PRODUCTION_GUARDS=false` 仅供独立本地开发，不列为生产恢复措施。

### 8.3 恢复正式鉴权

1. 恢复原快照对应的部署配置，确认 `SSO_TOKEN_REQUIRED=true`、`PRODUCTION_GUARDS=true`；清除覆盖它们的旧前缀及临时 override，恢复 Portal SSO。
2. 按既定策略重建相关实例，确认每个实例使用正确镜像、seed 和配置；只核对非秘密开关，不输出 token 或 Secret。
3. 撤销临时凭据、清理临时放行规则；保留入口隔离，完成下一节的负向与正向验收后，最后恢复正常入口。
4. 不整体回滚 PVC、不删除加密主密钥或会话/配置数据库。涉及数据格式变化时单独做备份及版本兼容检查。

可先做不携带凭据的 HTTP 检查（以下为文档示例，本轮未执行）：

```sh
curl -i --max-time 10 http://<host>:<port>/portal-api/sso/status
curl -i --max-time 10 http://<host>:<port>/portal-api/alarm-workorders
```

状态接口 200 只证明公开入口可访问，不能代表鉴权全面通过。有效角色、审批、自动协同和文件下载仍须使用授权测试会话完成。
