# 业务技能的 MCP 与脚本通道

在数字员工的 MCP 管理页使用现有“启用/停用”开关，无需新增环境变量。配置按数字员工工作区隔离，以工作区 `drivers/` 中的 DriverCard 为准；不要修改已迁移的旧 `mcp.clients` 配置来切换通道。

## 行为

- 停用或未配置：对应业务技能直接使用已有脚本，不先尝试 MCP。仍需安装技能并配置脚本所需地址、凭据、依赖与授权。
- 启用且连接就绪：使用 MCP 暴露的工具，调用时仍执行原有权限与审批检查。
- 启用但尚未就绪或配置损坏：明确报告状态，不当作“未配置”转脚本。
- 发现工具时，一个 Server 故障不影响其他 Server。已确认的连接故障允许只读操作使用已有脚本一次；未知发现错误不自动降级。
- 空结果、可解析的业务错误、鉴权失败、权限拒绝或工具白名单排除，不自动切换到脚本。
- 写请求已经发出而结果不明时，不用脚本重放。普通巡检脚本使用 `--no-notify`，通道变化不会授权发送通知。

保存后，新请求读取新配置。启用需等待后台连接就绪；停用后，即使后台还没卸载旧连接，工具发现和调用入口也会检查持久化开关。已发出的远程调用不能撤回。

工具白名单和权限元数据也在调用前刷新：移出白名单的工具不会继续通过旧会话调用；空白名单表示不暴露工具，不等于未配置 MCP。

## 支持的部署技能

| MCP Driver key | 技能 |
| --- | --- |
| alarm | real-alarm、alarm-analyst |
| cmdb-query | zgops-cmdb、inspection-analyst、alarm-analyst |
| inspection | inspection-analyst、alarm-analyst |
| resource | resource-insight-query、monitoring-overview-query |
| order | order-workflow |
| web-check-app | web-availability-monitor |

这里使用稳定的 Driver key，不使用可编辑的显示名称。自定义 Server 不会自动获得脚本替代能力。复合技能按能力路由，例如 cmdb-query 停用而 inspection 启用时，CMDB 查询使用脚本，指标查询使用 MCP。

## 排查

运行时向 Agent 提供 `Skill execution routes`，每条记录包含 skill、driver、route、reason 和已暴露工具名，不包含凭据。

- `script / mcp_disabled`：显式停用。
- `script / mcp_not_configured`：没有对应配置。
- `mcp / mcp_ready`：已有可调用工具，权限仍在调用时检查。
- `unavailable / mcp_not_ready`：已配置启用但未就绪。
- `unavailable / driver_configuration_error`：配置损坏或协议不匹配。
- `unavailable / driver_state_unknown`：无法读取工作区状态。
- `unavailable / mcp_discovery_failed`：工具发现发生未知错误。
- `unavailable / mcp_transport_unavailable`：已确认连接/传输异常，只读操作可一次脚本回退。
- `blocked / no_exposed_tools`：没有暴露工具，不推断为未配置，也不绕过白名单。

路由摘要指导 Agent 使用现有技能脚本，并不是新的脚本执行器；脚本仍走现有工具与授权链路。自动化测试覆盖配置解析、真实 DriverManager 调用边界、技能契约、界面文案与部署同步，不能替代目标环境凭据和真实业务接口联调。
