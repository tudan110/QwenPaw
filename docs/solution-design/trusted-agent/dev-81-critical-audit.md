# dev-81 关键活动审计：部署与验收

入口：Portal → 设置 → 安全与审计 → **关键活动审计**。需要后端验证过的管理员会话，前后端一起发布。

## 记录范围

| 类型 | 已接入 | 结果口径 |
| --- | --- | --- |
| 策略决策 | 已接入治理器的工具策略判定 | 允许、拒绝、需审批等，不是实际执行结果 |
| 工具执行 | 已接入治理器的工具执行 | 开始和实际观测到的终态分别记录，以调用编号关联。未收到终态、普通返回均不能当作业务成功 |
| 治理操作 | 权限申请与审核、访问名单、任务控制与处置、受控资料、告警导出与限额、指定模型／MCP／安全策略配置和本页 CSV 导出 | HTTP 层结果；2xx 表示请求完成，不代表业务成功。具体动作见 `activity_middleware.py` |

五项核心字段在表格及 CSV 中均有独立列。入口优先采用服务端验证的登录主体，无可信用户时区分智能体主体和未验证身份。治理操作不采集请求正文、凭据、查询参数；只留端点或不透明对象 ID。现存的工具策略历史可能含原始目标字符串，关键活动页面和 CSV 不回显路径、命令及任意参数。未接入治理器的后台活动、SSO 层提前终止的认证拒绝和其他独立业务账本不自动汇入本页，应另行核对审计范围。

## 本地防护与留存

- 启动时对 `WORKING_DIR/governance/audit.db` 做非破坏性迁移、生成 SHA-256 校验链。旧记录是**首次建立基线时**核对过的历史副本，不证明更早的真伪；旧时间格式的原始表仍保留。新记录与校验链同事务提交。
- 日志及校验表只追加，SQLite 拒绝更新、删除和替换已有行。关键请求如果不能写入开始记录，则拒绝执行；终态写入失败时保留开始记录并报错到服务日志，不假装回滚已完成的业务。
- 本地不按条数或到期自动清理，管理员页面没有修改或删除入口。普通留存基线为 **6 个日历月**；部署参数 `QWENPAW_AUDIT_EXTENDED_RETENTION_MONTHS` 默认 **36 个日历月**，可配置更长。36 个月是保守的部署默认值，不是对所有重要数据或个人信息的法定期限判断。由数据责任人核定适用范围、期限和暂停销毁要求；因为快照可能混有多种记录，整批按适用的最长期限上锁。未确认分类的快照不得按普通期限缩短。
- 以专用服务账户挂载持久卷，限制数据库、WAL、SHM 文件和父目录访问；禁止将卷开放给工具、共享文件服务或通用写账号。服务账号、不可变存储写入账号、留存配置管理员应分权。不要直接复制在线 `audit.db`、手动 `VACUUM` 或重建其行号。

## 独立不可变归档（生产验收必做）

本地触发器不能阻止有宿主机权限的主体替换整个库。没有独立不可变归档及恢复演练时，页面只能证明本地控制，**不能证明已满足独立防删除或现场留存要求**。

1. 在独立账户与故障域启用受保留锁保护的对象存储（WORM、禁止覆盖和提前删除）。根据批准的留存期限配置锁定。为独立归档任务设置周期、监控最后成功时间、告警阈值和磁盘配额；重试失败批次，不因失败删除本地证据。
2. 定时使用同镜像里的归档工具生成一致性快照。首次可不带 `--previous-manifest`，此后从独立归档读取最近一次已确认的清单作为锚点：

   ```sh
   python -m qwenpaw.governance.audit_archive /restricted/audit-staging \
     --previous-manifest /restricted/verified-previous-manifest.json
   ```

   工具读取已提交的 WAL 数据，校验失败不会产出待上传批次。部署任务必须将批次中的 `audit.db` 和 `manifest.json` 一同上传到独立存储并核对两个对象的锁定截止日、大小和可读取性。工具只负责本地暂存及校验，不自动配置对象存储或上传，也不删除在线日志。快照包含完整历史，应加密并严格限制读取权限。
3. 恢复演练在隔离目录使用 `--database` 指向下载的快照，或在隔离服务中用对应清单的 `checkpoint` 验证；再将同一锚点贴到生产页面校验，确认生产库仍包含该历史。单独下载锚点不能恢复日志，也不能作为完成归档的证明。
4. 验收材料应包括：管理员／普通账号权限验证；五项字段及拒绝、失败、未确认案例；本地更新、删除、替换被拦截；已保存锚点与恢复快照验证；归档保留锁实际截止日与无删权限测试；短暂归档故障后的重试及恢复；启用日期和容量告警。不要把演示样例或刚建立的基线当作已留存六个月的历史。
