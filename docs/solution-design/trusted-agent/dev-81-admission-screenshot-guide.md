# dev-81 可信检验：调用准入取证指引

适用条款：3.2.1-4（302-1.4）调用准入与权限范围；3.2.1-5（302-1.5）未知接口拒绝。以启用了生产守卫的送检环境为准。下面的规则自检不会连接实际目标，也不会读取凭据。

| 建议截图位置 | 操作 | 截图能说明的范围 |
| --- | --- | --- |
| Portal → 设置 → 组件治理与策略 → 调用准入 | 使用 AI 管理员登录。确认生产守卫状态，点「展开明细」。截图包含平台工具与 Skill、业务 API、MCP 的准入与操作影响。组件级权限范围、用途和风险可配一张「组件清单」。 | 当前配置、代码中的实际分类及约束。脚本候选列表不等同于已安装、启用或已通过校验。 |
| 同页 → MCP 准入自检 | 点「验证当前准入规则」。在 81 的主机模式下，期望「默认回环主机：允许」和「未登记测试地址：拒绝」。若改为合法的精确白名单，页面才显示精确端点模式；复验登记允许、未登记拒绝。 | 后端实际策略对这两个输入的判定。主机模式不能证明同主机不同路径已被隔离，也不能证明任何 MCP 服务已正常联通，或所有未知业务 API 都被拦截。 |
| Portal → MCP 管理 → 对应工作区及服务 | 对已接入的服务打开工具策略，截图服务开关和实际配置的允许、审批或拒绝。未启用的服务如实显示状态。 | 实际登记的服务与工具策略。若要证明工具能调用，需另做真实只读调用。 |
| Portal → 自监控 → 链路追踪 → 原会话 → 权限校验 / 异常核查 | 在 Portal 用管理与普通账号分别执行同一个正常 CMDB 资产查询。各自在自己有权查看的链路中核对本地准入及智观返回。若出现脚本拒绝，可在对应会话核对语法拒绝或完整性拒绝。 | 区分本地准入、上游数据权限与业务执行结果。只有取得真实结果才记录已验证；没有异常时无需人为制造生产异常。 |

现场复测前先核对 Portal、后端与部署种子的版本。先从告警分析、资源查询等只读流程回归。若某个工作区仍使用现场保存的旧 Skill，先查该脚本的实际拒绝原因及完整性状态；不要移除现场新增文件，也不要关闭生产守卫。
