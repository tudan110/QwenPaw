# dev-81 可信检验：调用准入取证指引

适用条款：3.2.1-4（302-1.4）调用准入与权限范围；3.2.1-5（302-1.5）未知接口拒绝。以启用了生产守卫的送检环境为准。下面的规则自检不会连接实际目标，也不会读取凭据。

| 建议截图位置 | 操作 | 截图能说明的范围 |
| --- | --- | --- |
| Portal → 设置 → 组件治理与策略 → 调用准入 | 使用 AI 管理员登录。确认生产守卫状态，截图「逐项准入控制」中的调用对象、权限边界、风险等级及来源、准入配置。也可从「安全边界总览 → 配置调用准入」进入同一策略。 | 区分系统基线与人工评估，以及「禁止调用」与「沿用既有策略」。「沿用」不证明上游授权；基线清单不等同于已安装、启用或已通过校验。 |
| 同页 → MCP 准入自检 | 点「验证当前准入规则」。在 81 的主机模式下，期望「默认回环主机：允许」和「未登记测试地址：拒绝」。若改为合法的精确白名单，页面才显示精确端点模式；复验登记允许、未登记拒绝。 | 后端实际策略对这两个输入的判定。主机模式不能证明同主机不同路径已被隔离，也不能证明任何 MCP 服务已正常联通，或所有未知业务 API 都被拦截。 |
| Portal → MCP 管理 → 对应工作区及服务 | 对已接入的服务打开工具策略，截图服务开关和实际配置的允许、审批或拒绝。未启用的服务如实显示状态。 | 实际登记的服务与工具策略。若要证明工具能调用，需另做真实只读调用。 |
| Portal → 自监控 → 链路追踪 → 原会话 → 权限校验 / 异常核查 | 在 Portal 用管理与普通账号分别执行同一个正常 CMDB 资产查询。各自在自己有权查看的链路中核对本地准入及智观返回。若出现脚本拒绝，可在对应会话核对语法拒绝或完整性拒绝。 | 区分本地准入、上游数据权限与业务执行结果。只有取得真实结果才记录已验证；没有异常时无需人为制造生产异常。 |

可在隔离验收环境选用 `get_current_time` 做禁用验证：记录初始状态，设为「禁止调用」并填写理由，保存后刷新并点「验证准入」，应显示「策略判定：拒绝」。如需真实执行证据，用同一测试智能体尝试该工具并核对拒绝；最后恢复「沿用既有策略」。自检不执行工具，不能用于证明网络连通或既有授权通过。配置按同一后端工作目录生效，不覆盖部署名单，不中止已发出的请求，也不关闭 MCP 后台连接。受管脚本逐项限制依赖生产守卫，整个 Shell 工具的禁用不依赖它。

现场复测前先核对 Portal、后端与部署种子的版本。先从告警分析、资源查询等只读流程回归。若某个工作区仍使用现场保存的旧 Skill，先查该脚本的实际拒绝原因及完整性状态；不要移除现场新增文件，也不要关闭生产守卫。

## 402-2.1：系统安全边界及删除保护

1. 在 Portal 以已验证的管理员登录，打开「设置 → 安全与审计 → 安全边界总览」。保存后端读取时间、状态和配置来源；这是当前响应实例的配置证据，不是集群各副本、网络隔离或业务动作均已验证的证明。
2. 在「全局删除保护」点「校验知识库删除规则」。自检直接调用知识库的后端策略判断，不读取资料、不发起删除、不验证用户授权。保护生效时显示「拒绝彻底删除」；否则显示「未被全局保护拦截」，不能记为通过拒绝验证。归档不受该规则阻断，实际归档可另用合成资料验证。
3. 「启用保护」是正式配置变更，不是自检步骤。仅管理员可在当前运行配置可写且无环境变量覆盖时确认开启；成功后当前后端的后续请求即按新值判断，无需重启。禁止为取证自行更改共享环境；多副本应由运维核对同一部署策略，解除保护也由运维办理。
