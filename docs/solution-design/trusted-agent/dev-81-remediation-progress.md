# dev-81 首批整改与验证

本分支补齐验收所需的产品能力，Portal 是用户端。以 [57 个截图位置](dev-81-inspection-evidence.md) 为唯一取证索引。本页记录首批已实现的子能力；同一检验编号的其余要求仍须实施或取证。

| 原件位置 | 本批实现 | 仍须完成或验证 |
| --- | --- | --- |
| 301-1.1、301-1.2；401-2.1、401-2.3 | 启用独立样品配置后，Portal 聊天的创建、列表、详情、更新、删除、流式运行、历史恢复和后台查询使用服务端验证的用户范围。聊天停止必须命中本人会话。生产保护同时拒绝通用工具直接读会话存储。 | 校验真实 SSO，处理存量历史归属；隔离附件、报告、缓存、长记忆、知识库、其他业务资源和跨智能体调用。两账号场景只验证普通聊天 API。 |
| 301-2.1 | Portal 停止按钮显示后端受理，以及本地运行实际取消、结束或异常；等待清理达到预算时显示终态未确认。浏览器停止接收和服务端任务终态分开。 | 测现场控制延迟；补充持久控制、任务暂停/续跑、业务补偿、紧急关停、故障降级。此处的取消没有远程撤销或业务回退语义。 |

管理者可在独立、非生产样品中配置：

- `QWENPAW_SSO_TOKEN_REQUIRED=true` 与 `QWENPAW_PRODUCTION_GUARDS=true`。
- `QWENPAW_TRUSTED_CHAT_ISOLATION=true`：仅供独立样品验证。启用后旧共享会话不会按用户名重新分配或显示。验证和迁移应使用数据副本；旧会话需要以可信的归属记录核实后另行迁移，不能批量挂给第一个登录用户。
- `QWENPAW_MCP_ALLOWED_ENDPOINTS`：JSON 数组，每项含 `transport` 和 `url`。例如 `[{"transport":"streamable_http","url":"https://mcp.example.invalid/mcp"}]`。实际 URL 由样品部署提供，SSE 的接收和发送路径均须登记。不配置时沿用当前按主机的兼容规则；`[]` 明确拒绝全部远程 MCP。仅对受控的已验证环境启用。
- 采样时用同批样品的版本或摘要作为 `--sample-version`，由运行者输入实际只读 URL；使用新目录保留 `requests.jsonl` 和 `summary.json`。样品如需认证，可从 `QWENPAW_EVAL_ACCESS_TOKEN` 注入临时访问令牌。样品 URL、所测功能与性能承诺另外写入检验报告。

本地验证使用隔离数据。操作证明包括 Portal 执行审计实际读取测试数据库、同一调用编号的开始和成功状态、当前页导出，任务取消、晚清理、主动结束、未启动时取消，双账号聊天 API 越权拒绝，以及 MCP 同源路径准入。采样工具仅在回环服务短跑；正式取证仍须按 Word 的实际送检样品重新采集。

后续实现依赖：先盘点并收敛真实样品的可用功能与已授权对象（W0–W2），再接入高风险操作的确认、恢复和应急控制（W3–W4），随后覆盖多模态、敏感数据、外联、全链路审计与组件交付（W5–W8），最后在冻结样品完成业务效果、性能、演练和截图复核（W9）。企业披露材料、SLA、实际部署配置、长期观测、保留策略及不适用判定由相应责任方出具或确认。
