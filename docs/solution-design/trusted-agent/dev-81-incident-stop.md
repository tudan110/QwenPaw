# 402-2.4｜Portal 异常中止与处置记录

入口：**设置 → 安全与审计 → 异常中止**。使用已验证的 AI 管理员账号。要求当前后端已启用 `QWENPAW_TRUSTED_CHAT_ISOLATION`；如果尚未启用，应先核对现场会话归属及迁移影响，不能为截图直接变更生产配置。

## 处置步骤

1. 发现风险后，在页面选择「启动异常中止」，登记触发分类并确认。后端先持久化暂停状态，再对本服务实例中登记的 Portal 流式对话发出取消请求。待发送的流事件会丢弃，已发送的数据无法撤回。
2. 刷新状态，核对「入口状态」和「处置台账」。展开对应批次，检查操作者、时间、会话与轮次 ID、停止状态和会话检查点是否保存。`待确认停止`、`无法确认`、`未取得处置结果`都不能当作已停止；没有运行任务也不会登记为已确认取消。
3. 复核风险和现场状态后，选择「复核并恢复」。这只恢复新请求准入，不重启已停止的任务，不撤销已完成的操作。恢复绑定到复核的批次，台账记录复核操作者与时间。

建议截图同一批次的入口暂停、实际任务处置结果及检查点状态，处置完成后补充恢复记录。台账随本地控制状态保存，保留最近 101 批，仅记元数据；原会话检查点由会话存储维护，台账不是正文或工具参数的归档，也不是不可篡改凭证。

**范围**：人工触发、单服务实例、受管 Portal 流式对话（包括仅模型、继续回复及 CMDB 重试）。其他渠道、独立后台作业、其他副本、已经送达的远程请求，以及外部网络隔离、自动风险识别均不在此控制范围。外部处置要与网关、远程服务及数据安全记录分别核实。
