# Portal 智能体权限与链路取证（401-2.4、401-2.6）

## 401-2.4：对当前智能体的实际授权

在 Portal 的当前智能体对话界面打开 **智能体权限**。列表来自该智能体的工作区：有效 Skill、已配置的 MCP 服务，以及当前智观登录账号对每项能力的授权状态和到期时间。普通用户只能调整自己在当前智能体上的授权。工作区未启用的服务不能由个人开启，用户的选择也不会扩大上游数据权限或覆盖管理员策略。

| 操作 | 会怎样 | 取证位置 |
| --- | --- | --- |
| 关掉 `zgops-cmdb` | 智能体不再加载该 Skill。后端阻止受管的 `/zgops-cmdb`、脚本调用和 Portal CMDB 精确查询（包括中止后的继续查询）。 | 权限列表显示“已撤销”；在同一智能体发送 `/zgops-cmdb 查询资产 …`，显示没有使用 Skill；链路的“权限校验”记录拒绝。 |
| 恢复默认或临时允许该 Skill | 恢复默认仍受原工作区配置限制；临时允许 15 分钟，到期回到撤销。对已有 CMDB 权限的账号可顺利查询；无权限的账号仍由智观拒绝。 | 同账号同一条实际 CMDB 查询；截有时效的权限行，以及“权限校验”中本地和智观的结果。 |
| 首次使用未临时授权的 MCP 工具 | 已通过平台策略的调用暂停等待本人选择，弹窗显示智能体、服务、工具、范围和到期时间。允许仅放行当下等待的这一次调用；拒绝、撤销或超时后不发出工具请求。 | 在接有实际只读 MCP 的验收样品上，先截授权弹窗；两轮分别选择“拒绝”和“允许本次”，在链路中截相应的判定。 |
| 撤销 MCP 或临时允许 | 撤销后不再向本人的该智能体提供此 MCP 的工具，已生成但尚未执行的调用也会重新检查；15 分钟临时允许仍受工作区、MCP 工具及生产策略限制。 | 当前智能体的 MCP 列表、有效期、撤销后复测；另一个账号的设置应不变。 |

Skill 和 MCP 是不同能力。若某个独立 MCP 与某个 Skill 能完成同一业务，要禁止此智能体通过两条受管路线完成同类动作，应分别撤销两项。独立的 Portal 业务页面、定时任务、外部系统和代理入口不随此个人开关关闭。已在上游执行的操作不会被追溯取消。通讯录、相册和位置可以标为当前 Web 部署样品不涉及的采集项，前提是相关设备采集入口不在送检范围内；此页不会模拟设备许可。未知或高风险工具仍以现有管理权限和强制审批为准，个人允许不会放宽生产保护。81 上若当前智能体没有启用实际 MCP，权限列表会据实显示；弹窗须在接入只读 MCP 后再验。

## 401-2.6：在原链路中补权限证据

原来的工具列表说明“执行了什么、是否成功、耗时多少”。对新产生的链路，在 **权限校验** 页签可看调用方、会话用户标识、目标、权限范围、授权依据、有效期和允许/拒绝；MCP 的待确认与最终决定共享一个校验编号。普通账号在启用会话隔离时只查看自己的链路，AI 管理员保留运维视图。记录不写令牌、MCP 实参或 CMDB 资产内容。

现阶段可以取证：

- **跨系统**：默认入口的 `lookup_portal_cmdb_asset` 只读精确查询。链路分别显示本地准入和来自智观的接受、401、403 或未确认。可以用两账号查同一对象证明权限未自动扩大；若普通账号 401，不能把它描述成已经验证了资产级数据范围。
- **跨工具**：MCP 一次明确授权的等待、允许或拒绝，以及已接入的 Skill 撤销拦截。MCP 的用户确认只约束这一调用，不等于把当前用户的智观凭据转给 MCP，也不代表所有工具都纳入了同一授权体系。
- **跨智能体**：旧的 `chat_with_agent` 工具记录只能证明发生过调用，不能证明有独立委托、有效期或逐跳限权。此轮仍待补。

跨智能体建议先接一条实际的只读协同作为验收样例。用户确认“由主智能体委托查询智能体对指定资源做一次只读查询”后，由服务端签发短期、仅此任务有效的委托。记录根任务、父调用、目标智能体、准许的操作和资源范围、有效期、授权人及判定编号。接收方在每次实际工具调用前取 **本人上游权限 ∩ 父任务允许范围 ∩ 本次明确委托 ∩ 接收方权限**；未列在交集的操作直接拒绝。用户撤销或任务结束即失效，默认不允许再转派，不发送可复用的上游凭据。验收截图应同时保留同一链路的“委托签发 → 子任务只读允许 → 越界申请拒绝”三笔真实事件。完成这条链路前，401-2.6 保持部分具备。
