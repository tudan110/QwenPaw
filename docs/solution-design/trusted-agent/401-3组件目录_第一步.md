# 401-3组件目录：第一步

本次只增加独立只读导出工具，先整理真实组件目录，提供可检索、可截图的HTML报告和JSON明细。工具不接入应用启动、请求或工具执行链，不要求重启或部署应用。

## 对应原文与当前边界

| 401-3原文步骤 | 本次交付 | 尚缺内容 |
| --- | --- | --- |
| 1 组件清单、用途、权限、数据范围、风险等级 | 从已知来源收集目录和可取得的元数据；未知项明确标待核实 | 需审核权限、数据范围、风险等级，并核对交付环境的实际组件范围 |
| 2 独立授权、风险审查、最小权限 | 保留现有能力；本轮不增加执行规则 | 按组件核验实际生效的授权和审查记录 |
| 3 新增、升级、替换、下线安全核验 | 本轮不改安装或升级流程 | 完成变更审核与真实验证记录 |
| 4 数据流与保护、共享可追溯 | 目录保留数据范围字段 | 补实际数据流、处理方式与保护证据 |
| 5 漏洞记录、停用下线、隔离清理 | 本轮不自动扫描、停用或清理组件 | 补扫描记录、处置流程与真实演练 |

因此当前仍为“部分具备”，不能把生成目录报告记为401-3整项完成。

## 生成与查看

在仓库根目录执行（仅需Python 3.11及以上，无需安装项目依赖）：

```powershell
python scripts/component_inventory.py --output-dir outputs/component-inventory-review-01
```

生成`components.html`及`components.json`。用浏览器打开HTML，可按类型和文本检索；选择“技能”“MCP服务”等分类后截图。HTML直接打开即可使用，不启动Web服务、不增加公开接口。

默认仅采集仓库与`deploy-all/qwenpaw/working`交付模板。模板条目会明确标注为模板，不能当作81等环境当前正在运行的组件。

如需核对真实工作目录，显式传入目标路径；报告仍只代表配置声明，未验证加载或连通：

```powershell
python scripts/component_inventory.py --working-dir D:/path/to/working --output-dir outputs/component-inventory-review-02
```

每次使用新的输出目录，工具拒绝覆盖已有报告。输出目录不能在被采集的工作目录内。

## 采集范围与证据口径

- Python项目、Console的直接依赖声明；声明版本或版本范围不等于已安装版本，不是完整SBOM。
- 随源码提供的技能、插件清单与硬编码内置工具定义，标注为源码/仓库内容，不认定已启用。
- 交付模板和显式工作目录中的`config.json`、`workspaces/*/agent.json`内MCP、工具、`active_model`声明，以及技能目录。
- 技能只解析简单元数据，不执行技能或解析YAML自定义标签。摘要针对实际`SKILL.md`字节，仅为来源文件指纹，不能证明整个技能代码未被修改。
- 不读取凭据目录、`.env`、会话及知识库数据。不导出headers、env、args、OAuth或工具config；MCP地址只保留协议、主机和端口，移除用户名、密码、路径、查询和片段。
- 不读取全局Provider存储，因此继承模型可能缺失；动态插件、动态注册工具、其他外部服务、传递依赖仍需现场补核。
- 遇到不可读、无效JSON、过大或不安全来源时保留采集提醒，不能据此认定没有组件或检查通过。

报告中的权限、数据范围和风险等级先标“待核实”。下一步可以根据真实配置与组件审核逐项补充；本轮不依据名称自动生成“低风险”结论。

## 风险、验证与撤回

本次新增脚本、针对导出边界的测试和本说明，不修改现有鉴权、组件准入、网络策略、流式输出、执行控制或数据库。

针对凭据遗漏、URL脱敏、HTML注入、来源文件字节摘要、来源不变、无效配置、已有报告保护、工作目录写入限制与链接目录边界进行验证。测试用合成值，不访问模型、MCP或生产服务。

撤回时删除本次新增脚本、测试、说明和生成报告即可，不涉及应用配置或数据迁移。已生成的报告只证明采集时间对应的来源声明，后续修改组件后应重新生成。
