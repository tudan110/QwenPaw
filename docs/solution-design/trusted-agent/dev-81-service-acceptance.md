## 三 服务可用性协议建议稿

**以下为商务与法务签审底稿。**建议目标及赔偿比例仅用于讨论，须用实际能力、承载容量和履约条件校准。试验用 81 环境不自动适用正式交付 SLA。

### 服务范围与目标

在协议约定的服务时段、租户、配额与用量内，为《服务清单》所列受保障能力提供自然月可用性 **不低于 99.5%** 的服务目标。建议按 7×24 小时统计。核心链路包括智观认证后的门户对话、模型有效回复，以及协议列入的知识检索和授权业务查询。用附件固定每条核心路径的测试账号、输入、超时上限、成功终态和最小业务断言。

### 可用与不可用的判定

每分钟从约定用户访问侧对各核心路径执行固定、低负载的合成业务探测，采集标准成功终态和业务断言。例如主对话收到完整有效回复，知识库命中约定资料，CMDB 返回约定授权测试资产。任一受保障路径超时、异常终止、返回错误或未通过断言，该分钟判不可用；同一分钟多个失败只计一次。可由同口径备用探测或双方认可的原始记录补证；无有效证据的分钟记入不可用，不直接剔除。登录页、门户静态页和健康路由 200 不能代替业务探测。

### 统计周期和公式

以北京时间每自然月统计；首末不足整月时按实际应服务分钟计。有效统计分钟 = 应服务分钟 − 双方确认且符合协议的豁免分钟。月可用性 =（有效统计分钟 − 不可用分钟）÷ 有效统计分钟 × 100%。按未四舍五入的值判档；有效分钟为零则当期不判达标。举例：30 天且无豁免的月份共有 43,200 分钟，99.5% 对应最多 216 分钟不可用。

### 例外与依赖责任

建议仅豁免事先书面约定并在批准时段内发生的维护，以及有证据证明由客户侧唯一原因导致的影响；超出批准窗口或影响范围不予豁免。服务方选用并负责的认证、模型、检索、MCP 或业务连接器引发的受保障链路故障计入不可用，不因其是上游依赖而事后扣除。每项豁免保存事件、时间、影响路径及双方确认依据。

### 补偿与复核

| 当月可用性 | 建议抵扣受影响服务当月实付服务费 |
| --- | --- |
| ≥ 99.5% | 不触发抵扣 |
| ≥ 99.0% 且 < 99.5% | 5% |
| ≥ 95.0% 且 < 99.0% | 10% |
| < 95.0% | 20% |

建议服务方在次月 5 个工作日内提供统计报告。客户可在收到报告后 30 日内凭事件时间、请求编号或故障工单提出复核；核实后按当月单一档次在下一账期抵扣，无后续账期时按签署协议处理。正式协议须确定受影响服务的费用基数、合并事件规则、上限和争议处理；送检时展示签署页、指标附件及一次可复算月报。
