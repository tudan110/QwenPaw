## SRC-01：自定义凭据头脱敏与编辑保存

复核用虚构管理员和合成 MCP 配置调用真实 `GET /api/agents/gateway`，确认原实现会回显 `X-Access-Key` 等值。此证据不等于普通用户已读取现场秘密。

修复后，`headers` 容器复用 MCP Driver 的公开头名单：明确的 Accept、Content-Type、User-Agent、X-Client-Name 可以保留，其余非空值默认掩码；补充 access_key、secret_key 后缀识别。读取和保存使用同一敏感字段判定，避免响应掩码后把 `***` 写成真实凭据。

回归使用真实 Agent GET/PUT 路由验证：未知凭据头、编辑其他字段、MCP 客户端重排、替换单个凭据、仅调整 HTTP 头大小写、显式清空凭据。另验证嵌套列表按 name 匹配旧值，响应脱敏不修改运行对象。

## SRC-02：异步登录与续期响应覆盖新状态

原复现确认：JSON 读取等待期间发生退出、新登录或组件卸载，旧续期回调仍可能调用 setAuthToken。这是之前 AUTH-05 未覆盖的等待窗口；此前修复记录的概括过宽。

- 将 AuthGuard 拆为可直接挂载测试的组件，App 继续使用它保护业务页面。
- 本地凭据每次设置/清理均递增修订号。异步操作同时校验发起时的凭据和修订号，避免退出后又写入同一字符串的状态被旧请求误认。
- 在 fetch 和 JSON 两个等待点后都检查状态；卸载会终止请求。迟到的成功响应不能写回凭据，迟到的 401 不能清除新登录。
- 同步保护入口 `bootstrapSso` 的 session/login 响应，尊重等待期间出现的 signed_out 标记。自身清除旧会话后允许正常 Cookie 回退；显式关闭 SSO 时保留原生流程。

真实组件测试在修复前复现 7 个失败时序，修复后通过；覆盖续期、初始化、组件卸载、新登录、同值重新登录和 Cookie 回退。入口引导另外验证 session/login JSON 期间退出、替换登录态和 signed_out 标记。

## LIVE-01：已确定上游通用 500，不能按失效 Token 统一改成 401

2026-11-13 对 81 做只读复核，只使用人工无效字符串，不使用真实用户 Token。直接请求已配置的用户信息端点，确认返回：

```json
{"code":500,"msg":"内部服务器错误"}
```

上游 HTTP 状态为 200，没有明确的 invalid_token / invalid_grant / access_denied 标记。QwenPaw 把它作为上游异常返回 502 是保守且必要的行为；仅由这一响应不能区分坏凭据和认证服务自身故障。

本次应用端改进：HTTP 成功响应中若有明确的 OAuth 拒绝标记，优先映射为 401；普通业务 500、HTTP 5xx、非 JSON、重定向和缺身份继续按上游故障拒绝。补充诊断日志，仅记录 HTTP 状态、受限的数字业务码及固定分类，不记录 Token、响应正文/消息、URL 或身份字段。

**LIVE-01 的上游根因尚未关闭。** 要让现场人工无效凭据稳定返回 401，需要 INOE 用户信息服务明确返回认证失败的状态或业务错误码。本次不通过猜测“内部服务器错误”的含义来掩盖问题，也不宣称已修复其他平台的源码。
