# 通知推送协议

通知由现有 `scripts/send_analysis_report.py` 完成，沿用任务授权和渠道配置；用户禁止或工具/审批阻断时不绕过，记录原因。聊天报告、通知文案、文件导出不是发送动作，不能用输出「通知推送」章节或下载链接替代实际调用。

聊天最终回复仍按 `portal-card-protocol.md` 输出完整卡片报告，不附加第二份通知全文；发送失败也保留分析正文。用户要求「异常指标→根因方向→处置建议」时是通知内容的组织要求，不改变聊天报告的固定章节，也不构成导出请求。不要为了通知加载 `report-export`。

## 推送渠道

可按 `.env` 配置同时推送到：
- 应用推送接口（可配置为量子密信）：`POST /api/push/{token}`，请求体 `{title, content, type}`
- 钉钉：发送 `markdown` 消息，指标值使用逐条列表（移动端不支持表格）
- 飞书：优先发送 `interactive` 卡片，明确展示状态、全量指标和结论

## 配置优先级

1. 优先读取 Portal「高级功能 → 设置 → 通知」中的 `alarm-analyst 建单推送` 配置
2. 未设置时回退到 `.env` 中的 `ORDER_CREATE_NOTIFY_*` 变量

## .env 配置项

```bash
ORDER_CREATE_NOTIFY_PUSH_URL=
ORDER_CREATE_NOTIFY_DINGTALK_WEBHOOK_URL=
ORDER_CREATE_NOTIFY_DINGTALK_SECRET=
ORDER_CREATE_NOTIFY_FEISHU_WEBHOOK_URL=
ORDER_CREATE_NOTIFY_FEISHU_SECRET=
ORDER_CREATE_NOTIFY_TIMEOUT_SECONDS=8
ORDER_CREATE_NOTIFY_MENTION_ALL=true
```

## 通知内容要求

至少包含：
- `AI 告警分析报告`
- 告警标题
- 告警编号 (alarmId)
- 资源 / 设备信息
- 根因方向
- 处置建议（启用止血时紧急预案条目排最前、前缀 `🚑 `；通过 `--suggestions-json` 中 `stage:"emergency"` 的条目自动排序+加前缀，不再单独成段）
- 异常指标（如果有）

通知文案里必须明确这是 **AI 自动生成** 的分析报告。

## 列表格式规则（严格要求）

**任何字段只要包含多条信息（处置建议、异常指标等），一律使用 `1. 2. 3.` 数字序号列表，禁止使用 `- ` 短横线列表。** 短横线仅用于展示单个字段本身（如 `- 告警标题：...` 这种一行一个字段的场景），不能用来枚举同一字段下的多个条目。`send_analysis_report.py` 内部构建飞书卡片、钉钉 markdown、纯文本推送时，处置建议、异常指标等多条目内容必须走数字序号，不允许退回短横线。

## 详细展示模式（`ALARM_ANALYST_DISPOSAL_DETAIL_MODE=true`）

开关打开时，推送中的处置建议按三级分组输出，每组带标题和编号列表：

**飞书卡片 / 钉钉 markdown / 应用推送**：

```
🚨 紧急止血（立即执行）
1. 🚑 将受影响业务流量切换至备用链路 XXX 先行恢复
2. ...

🔧 根因修复（计划内操作 / 短期）
1. 更换故障光模块 XXX，建议业务低峰窗口操作
2. ...

🛡️ 预防措施（中长期）
1. 建立光模块参数基线定期采集，预测剩余寿命
2. ...
```

- 每级组标题前加对应 emoji（🚨 / 🔧 / 🛡️）
- 每级内仍使用数字序号列表
- 影响范围可控时紧急止血组可省略；无预防措施内容时预防措施组可省略

## 推送结果展示规则

- 以本轮脚本实际返回的 `notification.status` 和渠道结果为准；输出markdown时使用脚本给出的通知状态、渠道和错误，不能仅凭退出码0判断成功。脚本将渠道失败作为业务结果返回，进程成功不等于投递成功。
- 未调用发送脚本：`通知状态：未执行`；只有文案、导出文件或下载链接也是未执行，不预填已执行。
- 等待审批：写待审批；拒绝、超时或调用失败：说明本次实际限制，不重试、不换路径绕过。无法确认渠道结果时写结果未确认，不猜成功。
- `sent`：`通知状态：✅ 已成功推送`（表示渠道接口接受，不保证人工已读）
- `skipped`且`reason=webhook_not_configured`：写通知未配置；其他跳过说明实际原因，不冒充已发送。
- `partial`：写部分推送成功，列失败渠道和原因，不改为全部成功。
- `failed`：写推送失败及实际原因；报告正文仍完整交付。
- 应用推送正文使用纯文本列表，不发送 `**`、`>` 等 Markdown 控制符

## 推荐通知模板

影响范围大、启用紧急预案时，紧急预案条目排在处置建议列表最前，前缀 `🚑 `：

```
🔍 AI告警分析报告

- 告警标题：数据库锁异常
- 资源：db_mysql_001（10.43.150.186）
- 告警编号：alarm-001
- 根因方向：InnoDB 行锁竞争阻塞链 -> 死锁 -> 连接异常
- 处置建议：
  1. 🚑 先将受影响业务切换至备用 MySQL 实例恢复访问（需人工确认审批后执行）
  2. 查看死锁记录
  3. 排查长事务和锁等待关系
  4. 分析慢 SQL 日志确认热点写入
  5. 检查连接池配置
- 异常指标：
  1. 锁等待数：15（正常为 0，存在大量锁竞争）
  2. 慢SQL数：8（近期突增，与阻塞高度相关）

此报告为 AI 自动生成，请尽快跟进处置。
```

影响范围可控、未启用紧急预案时，处置建议列表不出现 `🚑 ` 前缀条目，其余不变。
